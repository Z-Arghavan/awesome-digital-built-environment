# Contributing

Thanks for helping improve this list. Please follow these guidelines.

## Before submitting

- Search the README to make sure the resource isn't already listed.
- Make sure the resource fits an existing category. If it doesn't, propose a new category in your pull request description.
- Prefer actively maintained tools, standards, or datasets over abandoned ones. If a tool is unmaintained but historically significant, note that in the description.

## Format

Each entry should follow this format:

```markdown
- [Name](https://link-to-resource) – short, factual description ending in a period.
```

- Use a single dash `–` (en dash) before the description, matching the rest of the list.
- Keep descriptions to one sentence. State what it is and, if useful, what makes it distinct (open-source vs proprietary, format supported, etc.).
- Link directly to the official source (project homepage, official GitHub repo, or standards body), not to a third-party mirror or blog post about it.
- Add entries in alphabetical order within their subsection where practical.

## How to submit

1. Fork the repository.
2. Add your entry to the relevant section.
3. Run a markdown linter locally if possible (this repo uses [awesome-lint](https://github.com/sindresorhus/awesome-lint) conventions).
4. Open a pull request with a short description of what you're adding and why it belongs.

Alternatively, open an issue with the resource link and a short description, and a maintainer will add it.

## Code of conduct

Be respectful and constructive. Disagreements about categorization or inclusion are fine, personal attacks are not.
